# 任务级增广与运行效率

## 增广单位

项目研究同一 agent 框架在多种生物学任务上的 task-specific GO 增广，数据库规则化整合和文献内容增广均属于实现路径。每类任务根据自身知识需求形成覆盖完整基因背景的共享 overlay。

GEARS 扰动预测是当前重点场景之一，其 overlay 统一用于全部扰动条件。通路、复合体和调控程序是该任务的知识类别，功能模块可以作为批量处理分区。

当前 GEARS / Norman 的投影背景为 3,127 个基因。102 个扰动靶点用于单独报告覆盖率，所有图基因均可获得新增属性。共享的人类知识快照可复用于其他扰动数据集，细胞情境作为独立限定保存。

完整覆盖指所有基因经过同一套筛查规则；无可用证据的基因以缺口记录。

## 新流程

1. **任务规划一次**：选择知识类别、数据源、证据标准、映射及情境规则，确定适用于整个基因背景的策略。
2. **按来源批量处理**：取得版本化快照，程序完成关联展开、ID 映射、筛选、去重、情境保留和全背景覆盖检查。
3. **按来源和规则审核**：核对数据语义与转换规则，对全部行运行程序检查，结合固定种子的分层抽样及异常复核。
4. **按任务知识需求获取文献**：按生物学主题、共享机制、论文或歧义类别组织证据包。文献可作为主要增广来源，也可补充数据库知识或处理证据缺口。需要实验解释或新概念的候选保留相应审核与共同出处。
5. **统一编译和冻结**：批量生成 gene–attribute 表和兼容的图输入，冻结后进行全部扰动的训练及评价。

结构化资源支持这条路径：[Reactome](https://reactome.org/download/current/) 提供完整映射和通路文件；[hu.MAP](https://humap3.proteincomplexes.org/download) 提供复合体成员及原始置信等级；[ENCODE](https://www.encodeproject.org/help/batch-download/) 提供批量文件及实验 metadata。数据资源的版本、证据语义和处理规则逐项记录。

审核结果明确区分数据库派生且通过程序检查的记录、样本审计覆盖的批次，以及逐条文献核验的实验断言。异常行隔离并统计，审核报告保留实际方法和样本 ID。

## 时间优化

- **批量数据处理**：LLM 决定规则，程序处理成千上万条行记录；最终响应返回文件清单和汇总。
- **证据复用**：同一论文的相关主张由一个证据包处理，多基因共同引用。新主张仍需核对支持范围。
- **数据和转换缓存**：原始快照按版本／哈希缓存；派生产物的键还包含 ID 映射、基因背景、筛选及情境规则版本。
- **控制上下文**：采用简短英文 task context，不重复传 schema，不打印完整基因列表及注释；跨阶段保留简短清单。
- **限定文献预算**：查询次数按整个任务分配，异常按组处理，未解决部分记录并隔离。
- **并发和增量执行**：独立来源 I/O 按限流规则并发；源版本或规则变化时重跑受影响的批次。模型复杂判断集中在任务规划及异常语义。

待实现的连接器和批量执行器需要实测 cold-cache、warm-cache 的耗时及吞吐。当前已调整任务卡、英文角色说明、批量产物 schema 和交接校验。

## 评价范围

评价重点是 agent 驱动的任务特定增广在多种任务上的规模、普适性及生物学效果。规则化数据库整合和文献增广都在范围内；agent 可参与来源、规则、执行与审核。

GEARS 场景中的覆盖、属性类别、GO 重叠、映射、吞吐和成本描述这一任务实例；多任务普适性对应不同任务类型中的评价。下游效果在增广冻结后测量。
