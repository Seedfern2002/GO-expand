# Per-module review interface

Return `batch_id`, `graph_revision` and one decision for every proposed module. Each decision contains `module_id`, `verdict` (`accept` or `defer`), `reason` and `evidence_ids`.

Assess the proposed action, identity, complete membership mapping and every incident edge together. Compare native hierarchy, source GO annotation, concept equivalence, process participation and computational aggregation according to their distinct meanings. Bind reasons to the declared scientific evidence and preserve deferred dependencies in the findings.

The controller validates evidence references and complete review coverage, holds affected dependencies and commits the accepted transaction before the next batch.
